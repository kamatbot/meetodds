## Implemented UX

### Notes

Every change writes a local recovery draft and schedules the existing native notes save. Writes are ordered per meeting across editor mounts. Older acknowledgements cannot clear a newer draft. Blur, page visibility changes, Cmd/Ctrl+S and unmount flush pending edits. Opening a meeting waits for an in-flight save before loading notes. Recovery distinguishes a draft based on the current saved version from a conflicting saved version; the latter requires an explicit choice instead of silently overwriting either copy.

The editor exposes Loading, Unsaved changes, Saving, Saved, failure Retry and recovered-draft states. A failed initial load blocks editing so an unreadable saved note cannot be accidentally replaced with an empty one. Local recovery-storage failure is disclosed. Local drafts are not described as encrypted.

### Recording state

A shell-level status component survives page changes. A generic recording-stopped event means capture stopped, not that files are saved. A recording-saved receipt confirms local files and can explicitly state no audio retained. Save failures remain visible through subsequent generic stop events until acknowledged. Library saving and summary generation are separately described.

The previous premature 'Audio is stopped and safe' text and decorative fractional progress bar are removed. These are status indicators, not measured progress percentages. A status component mounted after an event cannot reconstruct historical receipts; reconnect/snapshot support remains a follow-up.

### Export and sharing

The main export sheet defaults to the saved summary only. Personal notes, the full transcript and audio require explicit selection; an absent summary does not silently substitute private notes. The Share menu labels saved-content copy actions explicitly.

Availability is refreshed rather than using stale menu metadata. The sheet provides a selected-content preview, semantic checkbox/radio controls, SRT eligibility rules and a fresh-content comparison before export. PDF and Word reuse the existing formatted serializers and disclose their Downloads destination; native text/JSON/SRT/Markdown formats retain the system save dialog. Canceling text export stops the remaining audio export. Partial success is retained and reported if a subsequent step fails.

These actions use saved content. The separate legacy summary-toolbar exporter still reads current editor content; this iteration exposes the distinction rather than claiming all legacy entry points have been removed. Native export calls re-read their data, so the frontend comparison is not an immutable native snapshot transaction.

### Accessibility and interaction

The existing shell gains keyboard sidebar sizing (arrows/Home/End), ARIA min/max/current width, reliable pointer-capture cleanup, visible system focus outlines and reduced-motion rules. Shell/share shortcuts do not hijack editable fields, composition or dialog interactions. No new shell or duplicate meeting route was introduced.

## Before merging or shipping

1. Build/typecheck in the existing Mac workflow, then manually test notes edited immediately before switching meetings, closing a tab, backgrounding or force-quitting. Exercise write failure, retry and a recovered draft conflicting with the saved version.
2. Validate the lifecycle with actual native event ordering, including a late save failure, transcript-only recording, save timeout, navigation during save and app restart. Confirm failures cannot be covered by a generic success message.
3. Exercise every export format, file-picker cancel, text success/audio failure, changed saved content, no summary, non-Latin text and large documents. Verify existing PDF/DOCX serializer output separately; no serializer quality changes were made here.
4. Test keyboard-only navigation, VoiceOver, high contrast, reduced motion, small windows and sidebars at both limits. Remaining tab semantics, title-edit races, full shortcut coverage and empty/error states need an app-wide review.
5. Integrate draft cleanup with meeting deletion and the eventual privacy/data inventory; the recovery key is scoped by meeting ID but this patch does not hook every deletion or multi-window update. Do not represent localStorage as an encrypted vault or a cross-process compare-and-swap store.
6. Consolidate legacy/current-edit export entry points, implement immutable native export snapshots, and verify all changes together with the capture/summary branch. The full UX backlog, onboarding simplification and end-to-end latency targets are not complete in this milestone.

Main remains unchanged by this feature branch. Keep the PR in draft until native and rendered-UI validation is recorded.
